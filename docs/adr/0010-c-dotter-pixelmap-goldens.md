# ADR 0010 — C dotter pixelmap goldens; matching C where they differed

* Status: Accepted
* Date: 2026-10-28
* Deciders: petr
* Spec reference: §4.1.1 (window size), §4.1.2 (score matrix), §4.1.4–6
  (kernel, pixel scaling), §8.1 (golden tests)

## Context

Zero-tolerance pixelmap goldens against C dotter (plan item F4) were
pending a GTK2 build. The SeqTools 4.44.1 `dotter` package writes `.dot`
files in batch mode (`-b`) without a display, so the goldens can be made
from it directly.

The first comparison found five differences, all on dottir's side:

1. **Karlin alphabet.** C sums residue probabilities over the 20 standard
   amino acids (`getAlphabetSize`, `dotplot.c:1088`); dottir used all 24
   (`BZX*` included). And C divides the subject's counts by its *whole*
   length: the subject loop tests `!= NA` (24), which no residue code
   reaches, so `N`, `X`, `*` and other characters count towards the
   length but not towards any frequency. The probabilities are then
   renormalised, but the expected residue score is not. The repo's
   Karlin harness (`tests/golden_gen/karlin_ref.c`) had both of these
   changed, so the Karlin goldens agreed with dottir but not with C.
2. **Pixel factor.** C stores `0.2 * 256 / expResScore` in an `int`
   (truncation); dottir rounded.
3. **Reverse strand, last row.** C's `valueWithinRange` is inclusive, so
   the reverse pass also emits the row at `sIdx = slen - W`; dottir
   skipped it.
4. **BLASTX width.** C sizes the image `ceil(qlen / (zoom * 3))`; dottir
   used `ceil((qlen / 3) / zoom)`, one column narrower for some lengths.
5. **BLOSUM62 `*:*`.** C dotter's built-in table has −1; dottir's (from
   NCBI) had +1.

ADR 0009 also listed a sixth: a Karlin estimate below 3 was clamped to 3,
where C uses 10 (`dotplot.c:1126`).

## Decision

Match C dotter on all six; bump `PIXELMAP_FORMAT_VERSION` to 2 and
`LARGE_PIXELMAP_FORMAT_VERSION` to 3 (large mode shares the pixel factor).
Spec §4.1.1 now says: above 50 → 50, below 3 → 10.

Pin 15 C dotter pixelmaps in `tests/golden/c_dotter/` (cases in
`cases.tsv`, regenerated by `regen.sh`, inputs in `tests/corpora/c_dotter/`)
and compare them exactly in `crates/dottir-cli/tests/c_dotter_golden.rs`:
self-comparisons with and without the mirror, pairs, `-r`, `-v`,
Watson-only, Crick-only, `-W`, `-p`, BLASTP and BLASTX, zooms 1–7. The
Karlin harness is verbatim C again, with fixtures containing `N`, `X` and
`*`.

## Differences kept, by decision

* **Unknown residues score 0.** C scores an unknown protein character as
  `*` (−4 against everything) and DNA `N` as −4; dottir scores both 0.
  Plots only differ next to such characters. The golden corpus avoids
  them: `DA730641_noN.fasta` is the SeqTools example with its three `N`s
  replaced by `A`.
* **`-r`/`-v` on a sequence against itself.** C still treats this as a
  self-comparison (it compares the stored sequences before reversing),
  computes half the plot and mirrors it, although the reverse-complemented
  plot is not symmetric. dottir computes the whole plot.
* **Default zoom.** C picks the zoom from a 0.5 MB pixelmap limit (`-m`);
  dottir from its own memory limit and `--auto-zoom`. The goldens pass
  `-z` explicitly.

## Consequences

Plots change where the six differences applied: protein windows and pixel
factors (often by a few units), DNA plots against subjects with `N`s
(Karlin), the last reverse-strand row, BLASTX width, and `*:*` columns.
Saved `.dot` files from earlier dottir versions still load.
